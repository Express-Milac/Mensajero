# Certificación de carga — 16/10/2026

## Alcance

Validación del flujo de captura de Mensajero en dos niveles:

1. Pasarela HMAC + Laravel + SQL Server sobre `mensajero_test`.
2. Ráfaga real WhatsApp → Baileys → cola durable → Laravel → SQL Server.

Esta certificación corresponde al POC y no equivale todavía a certificación productiva.

## Nivel 1 — carga sintética controlada

La prueba `tests/Carga/CargaPasarelaSqlServerTest.php`, ejecutada con `phpunit.carga.xml`, generó:

- 1,000 eventos únicos.
- 4 grupos sintéticos autorizados.
- 25 remitentes distintos.
- 50 reintentos idénticos para validar deduplicación.
- 1,000 eventos persistidos, no 1,050.
- 1,000 entradas de buzón asociadas.
- 1,050 solicitudes HMAC procesadas.
- 2,121 aserciones.
- 0 fallos.

Medición observada en la estación local de validación:

- Tiempo de los 1,000 eventos: 20.910 s.
- Tiempo total incluyendo los 50 reintentos: 21.656 s.
- Rendimiento observado: 47.82 eventos/s.
- Memoria reportada por PHPUnit: 54 MB.

La prueba se ejecuta dentro de una transacción que se revierte al finalizar, por lo que no deja los 1,000 eventos sintéticos como datos permanentes en `mensajero_test`.

El archivo de prueba quedó aprobado posteriormente por Pint sin cambios funcionales.

## Nivel 2 — ráfaga real por WhatsApp

El operador informó que ejecutó una ráfaga controlada de 25 mensajes de texto independientes en el grupo de prueba autorizado, desde un participante distinto al número recolector. La evidencia SQL detallada de esa ráfaga no se había adjuntado al confirmar el resultado.

El operador indicó que las verificaciones solicitadas resultaron correctas:

- los 25 mensajes llegaron al flujo real;
- la secuencia esperada quedó completa;
- los eventos fueron capturados como mensajes de texto v3;
- no se observaron faltantes en la ronda;
- la cola durable de eventos terminó vacía.

**Estado de evidencia (19/10/2026): pendiente de conciliación.** Una inspección posterior de la base `mensajero_test`, sobre `chat_monitoreado_id=10020`, mostró 35 eventos históricos, únicamente 10 con `version_contrato=v3-recolector` y como último evento `id=11064` después del `id=10063`. Esos datos no respaldan, por sí solos, la presencia de 25 mensajes v3 nuevos. El salto del ID puede corresponder a identidades consumidas por los 1,000 registros de prueba sintética revertidos; no demuestra pérdida de mensajes. Antes de certificar esta ronda, verificar los 25 identificadores/secuencias, el grupo consultado, la base usada y el vaciado de la cola.

La ronda pretende validar el tramo:

`WhatsApp → Baileys → cola durable → HMAC → Laravel → SQL Server → ACK`.

## Resultado

**Solo el nivel 1 (carga sintética) está formalmente aprobado.** El nivel 2 conserva el reporte favorable del operador, pero está pendiente de reconciliar con los registros SQL disponibles:

- capacidad de la pasarela validada con 1,000 eventos;
- idempotencia validada con reintentos;
- distribución validada con varios grupos y remitentes;
- ráfaga real de WhatsApp: reportada satisfactoriamente por el operador, no corroborada aún por la consulta SQL del grupo 10020;
- cola durable al finalizar: reportada vacía, pendiente de evidencia verificable.

## Incidencia diagnóstica adicional (19/10/2026)

El último latido `ConexionWhatsapp 10014` se mostró con marca `2026-10-19T21:32:10Z` al usar el cast Eloquent, mientras que `now('UTC')` devolvió `2026-10-19T17:14:55Z`, es decir, un supuesto futuro de 4 h 17 min. El último evento se mostró en `2026-10-19T20:15:26Z`. El controlador guarda el latido con `now('UTC')`, la zona horaria de la aplicación es por defecto `America/Mexico_City` y SQL Server almacena `datetime` sin zona explícita; se investigará una doble interpretación al leer las fechas. No modificar relojes o datos antes de comparar valores SQL crudos, reloj PHP y reloj SQL Server. El estado `conectado` sin latido reciente no acredita salud real.
